DSRs lets you call language models with typed Rust structs. Define your inputs and outputs as a struct, and the library handles prompt formatting and response parsing.

This guide walks you through building your first typed LM pipeline.
Call `init_tracing()` once at startup if you want tracing-subscriber logging.

<Steps>
<Step title="Install DSRs">

Add to your `Cargo.toml`:

```toml
[dependencies]
dspy-rs = "0.7.3"
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
anyhow = "1"
serde_json = "1"
```

Or via cargo:

```bash
cargo add dspy-rs
cargo add tokio --features macros,rt-multi-thread
cargo add anyhow serde_json
```

These guides describe the repository checkout; a published release may not yet include every documented API. To use a local checkout, replace the version dependency with `dspy-rs = { path = "../DSRs/crates/dspy-rs" }`.

DSRs enables the `data` and `cache` Cargo features by default:

| Features | Dataset loading | Response caching | Execution history |
|---|---|---|---|
| Default (`data`, `cache`) | JSON/JSONL, CSV, Parquet, Hugging Face | Available | Available |
| `default-features = false` | JSON/JSONL | Unavailable | Available |
| `default-features = false, features = ["cache"]` | JSON/JSONL | Available | Available |
| `default-features = false, features = ["data"]` | JSON/JSONL, CSV, Parquet, Hugging Face | Unavailable | Available |

For a minimal build, use `dspy-rs = { version = "0.7", default-features = false }`. The `data` feature enables Arrow, Parquet, Hugging Face and CSV dependencies; `cache` enables foyer and tempfile. HTTP support remains part of the core library for LM providers and JSON/JSONL loading. Tests use tempfile independently as a development dependency.

The `cache` feature makes response caching available; enable it for an LM with `.cache(true)`. That setting returns an error when the feature is absent.

</Step>

<Step title="Configure the LM">

Tell DSRs which model to use. This sets a global default that all predictors will use:

```rust
use dspy_rs::{configure, init_tracing, LM};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    init_tracing()?;

    configure(
        LM::builder()
            .model("openai:gpt-4o-mini".to_string())
            .build()
            .await?,
    );

    Ok(())
}
```

<Note>
Set `OPENAI_API_KEY` in your environment. Other providers use their `provider:model` prefix and credentials. For native Ollama, use a model string such as `ollama:llama3.2` after downloading and serving that model.
</Note>

</Step>

<Step title="Define a signature">

A [signature](/docs/components/signatures) declares your task's inputs and outputs:

```rust
use dspy_rs::Signature;

/// Answer questions accurately and concisely.
#[derive(Signature, Clone, Debug)]
struct QA {
    /// The question to answer
    #[input]
    question: String,

    /// A clear, direct answer
    #[output]
    answer: String,
}
```

The doc comments become:
- **Struct docstring** → instruction for the LM
- **Field docstrings** → field descriptions in the prompt

</Step>

<Step title="Call the LM">

Create a [predictor](/docs/components/predict) and call it:

```rust
use dspy_rs::Predict;

let predict = Predict::<QA>::new();

// QAInput is auto-generated from your #[input] fields
let output = predict.call(QAInput {
    question: "What is the capital of France?".into(),
}).await?;

println!("Answer: {}", output.answer);
```

The `#[derive(Signature)]` macro generates `QAInput` and `QAOutput`. A call returns `Predicted<QAOutput>`: `output.answer` is a typed `String` accessed through `Deref`, and `.metadata()` holds the raw response, usage and field metadata. Use `.into_inner()` to take ownership of the output.

</Step>
</Steps>

## Complete example

Save this as `src/main.rs` and run it with `OPENAI_API_KEY` configured. For an offline prompt preview, run `cargo run -- --inspect-only`; it sends no provider request and requires no key.

```rust
use dspy_rs::{LM, Predict, Signature};

/// Answer questions accurately and concisely.
#[derive(Signature, Clone, Debug)]
struct QA {
    #[input]
    question: String,
    #[output]
    answer: String,
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let inspect_only = std::env::args().any(|arg| arg == "--inspect-only");
    let api_key = if inspect_only {
        "unused-for-prompt-inspection".to_string()
    } else {
        std::env::var("OPENAI_API_KEY")?
    };
    let lm = LM::builder()
        .model("openai:gpt-4o-mini".to_string())
        .api_key(api_key)
        .build()
        .await?;
    let predict = Predict::<QA>::builder().lm(lm.clone()).build();
    let input = QAInput {
        question: "What is the capital of France?".into(),
    };

    // Building a chat formats the prompt without sending a provider request.
    let chat = predict.build_chat(&input).await?;
    println!("{}", serde_json::to_string_pretty(&chat.to_json())?);
    if inspect_only {
        return Ok(());
    }

    let (prediction, _conversation) = predict.call_and_parse(chat).await?;
    println!("Answer: {}", prediction.answer);
    for entry in lm.inspect_history(1).await {
        println!("Raw output: {:?}", entry.raw_output);
        println!("Parsed output: {:?}", entry.output);
    }
    Ok(())
}
```

The same source is maintained as [00-quickstart.rs](https://github.com/krypticmouse/DSRs/blob/main/crates/dspy-rs/examples/00-quickstart.rs). From this repository, run `cargo run -p dspy-rs --no-default-features --example 00-quickstart -- --inspect-only`.

`build_chat` formats the prompt without a provider request or history entry. Pass that chat to `call_and_parse` to send exactly what you inspected and receive an updated conversation. The returned prediction contains `QAOutput`, rather than the complete `QA` signature.

History records executed calls, raw responses and parsed outputs independently of response caching. It is bounded and is not persistent storage. See [LM history](/docs/components/lm#inspecting-history) for capacities and module scopes. Avoid logging private prompts or responses in production.

## Predictors and modules

A `Predict<QA>` is already a module with one typed LM task. A `ChainOfThought<QA>` adds a reasoning field. Compose tasks by implementing `Module::forward`, call the pipeline with `Module::call`, and declare optimizer-visible leaves with `predictors!`. See [Modules](/docs/components/modules) for a complete implementation.

## Adding complexity

### Input formatting and rendering

Use `#[format("json")]` for serialization, or `#[render(jinja = "...")]` for custom field text.
See the full attribute reference in [Signatures & types](/docs/components/signatures) and runtime behavior in [Adapters](/docs/components/adapters).

### Custom types

When you need more than primitives, add [`#[Schema]`](/docs/components/signatures):

```rust
use dspy_rs::{Signature, Schema};

#[Schema]
#[derive(Clone, Debug)]
enum Sentiment {
    Positive,
    Negative,
    Neutral,
}

#[derive(Signature, Clone, Debug)]
/// Analyze the sentiment of the text.
struct SentimentAnalysis {
    #[input]
    text: String,

    #[output]
    sentiment: Sentiment,

    #[output]
    confidence: f64,
}
```

### Few-shot demos

Add examples to guide the LM:

```rust
use dspy_rs::Demo;

let predict = Predict::<QA>::builder()
    .demo(Demo::<QA>::new(
        QAInput { question: "What is 2+2?".into() },
        QAOutput { answer: "4".into() },
    ))
    .build();
```

### Constraints

Validate outputs with [`#[check]` and `#[assert]`](/docs/components/signatures):

```rust
#[derive(Signature, Clone, Debug)]
struct Rating {
    #[input]
    text: String,

    #[output]
    #[assert("this >= 1 && this <= 5")]
    score: i32,
}
```

### Multi-step pipelines

Chain [predictors](/docs/components/predict) for complex workflows:

```rust
#[derive(Signature, Clone, Debug)]
/// Summarize the supplied text.
struct Summarize {
    #[input]
    text: String,
    #[output]
    summary: String,
}

#[derive(Signature, Clone, Debug)]
/// Rate the summary from one to five.
struct Rate {
    #[input]
    summary: String,
    #[output]
    #[assert("this >= 1 && this <= 5")]
    score: i32,
}

struct SummarizeAndRate {
    summarizer: Predict<Summarize>,
    rater: Predict<Rate>,
}

impl SummarizeAndRate {
    async fn run(&self, text: String) -> anyhow::Result<RateOutput> {
        let summary = self.summarizer.call(SummarizeInput { text }).await?.into_inner();
        let rating = self.rater.call(RateInput {
            summary: summary.summary,
        }).await?;
        Ok(rating.into_inner())
    }
}
```

See [Modules](/docs/components/modules) for how to make this optimizer-compatible.
