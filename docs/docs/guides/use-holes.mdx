A `#[module]` turns your function body into a program graph: each step call becomes a node the system can print, tune, and serve. But some lines are just plain Rust, like uppercasing a string. The system cannot describe those lines as steps. Instead of refusing, it keeps each one as a hole: a named, typed black box. The graph knows the hole's name, its inputs, and its output type. It does not know what happens inside.

## Goal

Write plain Rust inside a module and have it become a clean, typed hole.

## Recipe

Give the `let` binding a simple type. That is the whole trick:

```rust
use dspy_rs::{module, predict};

/// Answer the question.
#[predict]
fn draft(question: String) -> String;

/// Rate the text from 1-10.
#[predict]
fn rate(text: String) -> String;

#[dspy_rs::Schema]
#[derive(Debug)]
pub struct QaOut {
    pub answer: String,
    pub upper: String,
}

#[module]
async fn qa(question: String) -> Result<QaOut, dspy_rs::ir::RunError> {
    let drafter = draft(question.clone()).await?;
    let upper: String = {
        let d: String = drafter.draft;
        d.to_uppercase()
    };
    let checker = rate(upper.clone()).await?;
    Ok(QaOut {
        answer: checker.rate,
        upper,
    })
}
```

Here `drafter` and `checker` are steps. `upper` is not a step call, so it becomes a hole named `upper`. Its input is `drafter.draft` (found automatically) and its output is a `String`.

## Allowed types

The type you write on the `let` must be simple, because it becomes a field in the program's interface:

- `String`
- integers (`i64`, `i32`, and friends)
- floats (`f64`, `f32`)
- `bool`
- `Vec<...>` and `Option<...>` of the above

Anything else is a compile error with a hint to pick one of these.

## When the compiler cannot infer a type inside the hole

Values that flow into a hole from earlier steps arrive through a decode step at run time. The compiler sometimes cannot work out their concrete type on its own. The fix is a small inner line with a type, as an anchor:

```rust
let upper: String = {
    let d: String = drafter.draft;   // the anchor
    d.to_uppercase()
};
```

The anchor tells the compiler "this incoming value is a `String`", and everything after it infers normally.

## See every hole in a module

Each module lists its holes in a constant called `OPACITY`. Check it to see what stayed opaque:

```rust
for hole in qa::OPACITY {
    println!("{} ({}): {}", hole.name, hole.kind, hole.excerpt);
    // upper (host): { let d : String = drafter . draft ; d . to_uppercase () }
}
```

Each entry carries the hole's name, its kind, the source expression, and the reason it could not be lowered to a step.

## Forbid holes

If you want a module that is one hundred percent steps, add `deny_holes`. Any line that is not a step call becomes a compile error:

```rust
#[module(deny_holes)]
async fn qa(question: String) -> Result<QaOut, dspy_rs::ir::RunError> {
    // only `let x = step(args).await?;` lines allowed here
}
```

## What a hole means for the printed program

A program with holes still prints and still runs. But the hole's Rust code is not in the printed file. The file only records the hole's name, its typed signature, and a fingerprint of the code, marked as `extern`:

```
upper = hole upper_hole (draft = drafter.draft) caps [] extern "a1b2c3d4e5f60718"
```

So only the binary that defined the hole can run the program, because only that binary has the code to bind by name. If you serve the printed file somewhere else, loading fails with a clear "host hole unbound" error. If you need a fully portable program, replace the hole with a sandboxed JavaScript hole in the `.dsrs` file, or with another step.

## Common mistakes

**No type on the `let`.** A hole must declare its output type. `let upper = ...;` without a type is a compile error that tells you to write `let upper: String = ...;`.

**Using a whole step result inside a hole.** Holes consume output fields, not whole results. Write `drafter.draft`, not `drafter`.

**Expecting the file to carry the code.** It does not. The printed program marks the hole as `extern`. Portability stops at the binary that defined it.
