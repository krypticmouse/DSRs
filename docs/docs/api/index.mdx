## Public imports and migration

Use `dspy_rs::prelude::*` or explicit root imports for the common signature, LM, module, evaluation, optimizer and trace APIs. The root and module facades use named re-exports, so adding a helper to an implementation module does not expand the root API.

Lower-level types use their public module paths:

| Previous root import | Explicit path |
|---|---|
| `RolloutCache`, `ScoreMatrix`, `CandidateSlot`, `CandidateEval`, `EvalOutcome`, `BatchEvalOutcome`, `GateOutcome`, `ParetoView`, `ParetoStatistics`, `Spend` | `dspy_rs::optimizer::engine` |
| `PromptingTips` | `dspy_rs::optimizer::mipro::PromptingTips` |
| `SimbaMove`, `SimbaStep` | `dspy_rs::optimizer::simba` |
| `StructuralStep` | `dspy_rs::optimizer::structural::StructuralStep` |
| `PredictBuilder` | `dspy_rs::predictors::predict::PredictBuilder` |
| `LMConfigBuilder` and generated builder state modules | Their defining module, such as `dspy_rs::core::lm` |
| `CompletionProvider` | `dspy_rs::core::lm::CompletionProvider` |
| `GLOBAL_SETTINGS` | `dspy_rs::core::settings::GLOBAL_SETTINGS`; prefer `configure`, `get_lm` and scoped `with_lm` |
| `DEFAULT_EVAL_CONCURRENCY`, `Rollout` | `dspy_rs::evaluate` |
| `is_url` | `dspy_rs::data::utils::is_url` |

The defining modules remain public. Response-cache types still require the `cache` feature. These changes intentionally remove automatic root exports, including generated builders and implementation-module aliases.

## Legacy typed-API migration

The former BAML/schemars surface is replaced by the current typed API:

| Former API | Current API |
|---|---|
| `BamlType` / `BamlSchema` | `#[Schema]`, which supplies Facet and serde support for nested user types |
| Untyped `Example` / `Prediction` / `MetaSignature` | Generated `SInput`/`SOutput`, `Predicted<SOutput>`, typed dataset rows and `Demo<S>` |
| `field!` | `ir::FieldDef` and the validated `ir::SignatureDef::build` for runtime-owned definitions |
| `sign!` | `#[derive(Signature)]` plus `Predict<S>`, or typed `#[predict]` steps in a module |
| `hashmap!` | `HashMap::from` |

Generated signature inputs/outputs and `#[Schema]` types serialize and deserialize
without adding serde derives manually. Typed augmentations add fields through
new output types; for example, `ChainOfThought<S>` adds reasoning while preserving
the base signature. Runtime-loaded programs keep owned definitions rather than
reviving the removed untyped predictor interface. Dataset `#[derive(Example)]`
is a row-projection macro, not the former untyped map container.

## Regenerating API pages

The pages are rebuilt from the working tree, not fetched from a registry, so they track your branch. From the repository root:

```bash
RUSTC_BOOTSTRAP=1 cargo rustdoc -p dspy-rs --lib --all-features -- -Z unstable-options --output-format json
RUSTC_BOOTSTRAP=1 cargo rustdoc -p dsrs-tools --lib -- -Z unstable-options --output-format json
RUSTC_BOOTSTRAP=1 cargo rustdoc -p dsrs_macros --lib -- -Z unstable-options --output-format json
RUSTC_BOOTSTRAP=1 cargo rustdoc -p dsrs-syntax --lib -- -Z unstable-options --output-format json
python3 docs/scripts/gen_api.py
```

Each generated page carries the crate version and commit it was built from. Run the five commands after any public-API change; CI can run them and fail on a dirty diff to keep this tab honest.
