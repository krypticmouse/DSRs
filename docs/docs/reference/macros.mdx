This page lists every macro exported by `dsrs-macros`, what each one accepts, and what each one generates. All names and rules here come from the macro source.

## `#[derive(Signature)]`

Turns a plain Rust struct into an LM call contract: typed inputs, typed outputs, and an instruction. The struct-level doc comment becomes the instruction text; field doc comments become field descriptions.

It only supports structs with named fields. Every field must carry `#[input]` or `#[output]` (never both), and the struct needs at least one of each.

### Field attributes

| Attribute | Applies to | What it does |
|---|---|---|
| `#[input]` / `#[input(desc = "...")]` | any field | Marks the field as an input. `desc` overrides the doc-comment description. |
| `#[output]` / `#[output(desc = "...")]` | any field | Marks the field as an output. `desc` overrides the doc-comment description. |
| `#[alias = "name"]` or `#[alias("name")]` | input or output | The name the LM sees, instead of the Rust field name. Two fields may not share one LM name after aliasing. |
| `#[format = "json"]` | inputs only | Renders the input value in a structured format. Allowed values: `"json"`, `"yaml"`, `"toon"`. Once per field. |
| `#[render(jinja = "...")]` | inputs only | Renders the input through a Jinja template. The template syntax is validated at compile time. Cannot be combined with `#[format]`. |
| `#[check("expr", label = "name")]` | outputs | A soft constraint on the value. The label is required. |
| `#[assert("expr")]` | outputs | A hard constraint on the value. A label is optional: `#[assert("expr", label = "name")]`. |
| `#[flatten]` | any field | Inlines a nested struct's fields. Cannot be combined with `#[alias]`, `#[format]`, `#[render]`, `#[check]`, or `#[assert]`. |

Constraint expressions accept Rust-style `&&` and `||`; the macro normalizes them to Jinja `and` and `or`.

### Rejected field types

These produce compile errors, with a hint in each message: bare function types, trait objects, tuples, `serde_json::Value`, maps whose key is not `String`, and the integer widths `u64`, `usize`, `i128`, `u128`.

### What it generates

For a struct `Name`, the derive emits `NameInput` and `NameOutput` helper structs (each with a `new(...)` constructor), field metadata tables, and the `Signature` trait impl (instruction, input and output shapes, field metadata).

## `#[predict]`

Declares one LM call as a bodyless function: the function is the signature. The doc comment becomes the instruction, parameters become input fields, and the return type becomes a single output field named after the function.

```rust
/// Answer the question accurately.
#[predict]
fn answer(question: String) -> String;
```

**Option**: `model = "@name"` selects a declared model by reference (the leading `@` is stripped). Anything else in the attribute is a compile error.

**Rules** (each is a compile error when broken):

- The function is bodyless (ends with `;`).
- Do not write `async`; the generated function is async automatically.
- No generics, no `self`, parameters must be plain identifiers.
- At least one input parameter and an explicit return type are required.

**What it generates**: a module `answer` containing the derived signature (`answer::Sig`, `answer::SigInput`, `answer::SigOutput`) and a `__dsrs_step()` metadata function, plus an `async fn answer(question: String) -> Result<Predicted<answer::SigOutput>, PredictError>` that calls `fx::predict` with the function's name as its params slot. That name is the link everywhere: `fx::Params::set_instruction("answer", ...)` overrides its instruction, and trace spans record the same name.

## `#[cot]`

The chain-of-thought variant of `#[predict]`: the LM produces a `reasoning` field before the output. Same rules and the same `model = "@name"` option.

The generated function returns `Result<Predicted<WithReasoning<answer::SigOutput>>, PredictError>`; `WithReasoning` auto-derefs to the output.

## `#[agent]`

Declares an LM plus tool loop as a bodyless function, the agent sibling of `#[predict]`.

```rust
/// Verify the draft against sources.
#[agent(model = "@fast", tools(search), max_turns = 6)]
fn research(question: String, draft: String) -> Vec<String>;
```

**Options**:

| Option | Form | Meaning |
|---|---|---|
| `model` | `model = "@name"` | Model reference for the loop. |
| `tools` | `tools(a, b)` | The `#[tool]` functions the loop may call, in order. |
| `stop_tools` | `stop_tools(a)` | Tools whose call ends the loop. Each must also appear in `tools(...)`; otherwise the macro errors with "stop tool `name` is not in tools(...)". |
| `max_turns` | `max_turns = N` | Turn bound for the lowered loop node (IR default is 8 when omitted). |
| `until_parse` | `until_parse = bool` | Stop when an assistant turn parses as the signature outputs (IR default is true). |
| `budget` | `budget(calls = N, tokens = N, deadline_ms = N, on_exhausted = finalize)` | Per-node spend limits. `on_exhausted` is `fail` (the default, the run fails) or `finalize` (one forced final round-trip without tools, then parse). |
| `context` | `context(max_history_turns = N, tool_result_max_bytes = N, playbook = "...")` | Context policy: history window, tool-result truncation, and a free-text playbook. |

The bodyless-fn rules match `#[predict]` (no `async`, no generics, no `self`, plain identifier parameters, at least one parameter, explicit return type).

**What it generates**: a module with the signature (`research::Sig` and friends) and a `__dsrs_step()` carrying the agent options, plus a standalone `async fn` returning `Result<Predicted<research::SigOutput>, PredictError>`. Inside `#[module]` bodies the call lowers to a first-class `AgentLoop` node. Called standalone it runs the static-lane tool loop (`Predict` with `ToolLoopMode::Auto`); the loop options (`max_turns`, `budget`, `context`) apply only to the lowered form.

## `#[tool]`

Declares a host tool: an ordinary function whose body IS the implementation. Parameters become the tool's input schema, the return type its single output field, and the doc comment its default description (an optimizable tool-description parameter once lowered).

```rust
/// Web search; returns result snippets with URLs.
#[tool(caps("net:search"))]
async fn search(query: String) -> Vec<String> {
    // real code here
}
```

**Option**: `caps("...", ...)` declares the capabilities the tool needs. Anything else is a compile error ("#[tool] accepts only `caps(\"...\", ...)`").

**Rules**: unlike `#[predict]`, the function has a body and may be `async`. No generics, no `self`, plain identifier parameters, at least one parameter, an explicit return type. Fallible tools may return `Result<T, E>` where `E: Display`.

**What it generates**: the original function unchanged (still callable as plain Rust), plus a module `search` with the tool's signature, a `rig` tool wrapper for host binding, and `search::__dsrs_tool()` metadata consumed by `#[agent]` and `#[module]`.

## `#[module]`

Compiles an ordinary async Rust function body into an IR `Program`. One parse, two projections: the executable function (typed boundary, runs through the interpreter, reads the ambient overlay) and `name::program()` (the same pipeline as a servable, optimizable, printable artifact). The two cannot drift because they come from one source.

**Options**: `caps("...", ...)` declares the program's capability ceiling; `deny_holes` makes any non-step expression a compile error instead of a hole.

**Accepted body shape** (straight-line only):

- `let x = step(args).await?;` where `step` is a `#[predict]`, `#[cot]`, or `#[agent]` function. Arguments must be ports: function parameters, prior `binding.field` accesses, or literals (`.clone()` and `&` wrappers are stripped).
- `let y: SimpleType = <any Rust expr>;` becomes a typed extern (host) hole. The type ascription is required and must be simple: `String`, `i64`/`i32`, `f64`/`f32`, `bool`, `Vec<...>`, `Option<...>`. Port-shaped subexpressions become the hole's inputs; the rest runs as native code bound by name at load; the artifact records it as `extern "<hash>"`.
- A tail expression `Ok(Struct { field: port, ... })` giving the program's output bindings.

The function must be `async`, cannot be generic, and must return `Result<Out, Err>` where `Err: From<dspy_rs::ir::RunError>`.

**What it generates**, inside a module named after the function:

| Item | What it is |
|---|---|
| `OPACITY` | A constant slice of `HoleReport` entries, one per hole-ized expression (name, kind, source excerpt, reason). |
| `program()` | The lowered `&'static Program`, linked at first use. Panics on link errors. |
| `try_program()` | The non-panicking form, returning `Result<&'static Program, &'static ModuleBuildError>`. |
| `env()` | The `RuntimeEnv` the module needs: its declared caps granted, the `default` model bound from the global settings when configured, `#[tool]` implementations bound, and extracted host holes bound. |
| generated test | A `#[cfg(test)]` test named `module_program_links_and_validates` that prints every `OPACITY` entry and fails the suite if `try_program()` errors. |

It also emits the executable `async fn` itself, which loads the interpreter once, reads the ambient overlay via `current_overlay()`, and runs with a default budget.

## `include_program!`

Embeds a `.dsrs` program artifact at build time.

```rust
dspy_rs::include_program!("programs/qa.dsrs");
let program: &'static dspy_rs::ir::Program = qa::program();
```

The macro expands in place to a module named after the file stem (`qa.dsrs` becomes `mod qa`; `-` maps to `_`) containing:

- `SOURCE: &str`, the embedded text (via `include_str!`, so rustc rebuilds when the file changes);
- `program() -> &'static Program`, which parses and validates on first access and panics on semantic errors;
- `try_program()`, the non-panicking form;
- a generated `#[cfg(test)]` test that forces full validation under `cargo test`.

The path resolves relative to `CARGO_MANIFEST_DIR`, with the invoking file's directory as a fallback base; absolute paths are used as-is.

**Validation layering**: the macro checks syntax only at build time (the `dsrs 1` pragma, keyword vocabulary, declaration shapes, balanced delimiters, strings, numbers, code fences). Types, dataflow, capability subsets, and all other semantics are checked by the real parser at first use of `program()` or `try_program()`, and at CI time by the generated test: run `cargo test` and a semantically invalid artifact fails the suite even if never executed.
