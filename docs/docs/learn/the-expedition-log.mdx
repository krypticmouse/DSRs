In Chapter 1, this book asked you to put one unexplained line at the top of `main` and keep it there. You did. It's time you knew what you've been paying for.

Every run of Front Desk since that day, every model call, every tool call, every answer, has been written down. What was sent, what came back, in what order, step by step. Not a summary. The whole journey.

That record is called a **trace**, and the right picture is an expedition log, or if you prefer machines to mountains, a flight recorder. It doesn't fly the plane. It remembers everything, so that later, you can know exactly what happened instead of what you *think* happened.

Chapter 9 left you with a specific misery: every "let me just try this" costs a live run, and after ten tweaks you can't prove today's desk beats Monday's. Both problems have the same solution. If the journey is written down, you can walk it again.

## Hold a run in your hand

The habit was ambient until now; here's the explicit form. Wrap any call in `capture` and get the run back as a value:

```rust
use dspy_rs::trace::capture;

let (out, trace) = capture(|| frontdesk(herman_ticket.clone())).await;
let out = out?;

let jsonl = trace.to_jsonl()?;
std::fs::write("runs/herman.jsonl", jsonl)?;
```

The module ran live, real calls and all, and the `trace` now holds each step. It serializes to JSONL: plain, readable, *diffable* text, one step per line. Sound familiar? The program became a text file in Chapter 6. Now each run is one too. The same move, applied twice: hold the program, hold the run.

Do this for twenty real tickets and commit the files. That's not ceremony; that little folder of recordings is about to become your test suite, your debugger, and, in two chapters, food for something hungrier.

## Strict replay: yesterday, for free

Now the move that makes recordings more than souvenirs. Run the module *against* a recording:

```rust
use dspy_rs::{replay, ReplayMode, Trace};

let trace = Trace::from_jsonl(&std::fs::read_to_string("runs/herman.jsonl")?)?;

let (replayed, report) = replay(&trace, ReplayMode::Strict, || {
    frontdesk(herman_ticket.clone())
})
.await;

assert_eq!(report.live, 0);
```

Each time the module was about to call a model, replay stepped in and served the recorded answer instead. `report.served` counts steps answered from the log. `report.live` counts real calls: **zero**. No API key. No cost. No flakiness, because the model can't give a different answer on a different day if the model was never called.

`Strict` means exactly what it says: if anything about the run no longer matches the recording, fail loudly and say where, rather than quietly going live. Which makes this a *proof*: a passing strict replay demonstrates your pipeline still behaves precisely as it did when the recording was made. Put it in a `#[tokio::test]`, run it in CI on every push, and regressions in a model-powered pipeline get caught the way ordinary regressions do. Tests that cover real model behavior, free forever.

## Until-divergence: pay only from the turn you took

Strict replay guards the past. The second mode funds the future.

You want to tweak the drafter's instruction, the Chapter 9 itch. Your pipeline runs scrub, then research, then draft. Your tweak touches only the last step. Why should trying it cost a full run?

```rust
let (out, report) = replay(&trace, ReplayMode::UntilDivergence, || {
    frontdesk(herman_ticket.clone())
})
.await;

println!("served {} free, {} live", report.served, report.live);
```

```text
served 2 free, 1 live
```

Replay followed the log while your run still matched it: the scrub and the research agent replayed free, served from the recording. At `draft`, your new instruction made the call *different*, so that call, and anything after it, went live. You paid for exactly one step: the one you changed.

Walk the logged route for free; the meter starts where you leave the trail. Ten variations of the drafter's instruction now cost ten drafts, not ten full expeditions, and the research agent's tool calls don't re-fire either: served steps never re-run their tools. Cheap tries compound. More tries is how programs get better.

## Detected, never declared

One question should be bothering you: how did replay *know* the drafter call was the changed one? You never told it what you edited.

Every call gets a fingerprint of exactly what was about to be sent: the full rendered prompt and the model settings. Change anything the model would actually see, an instruction, a demo, an input flowing in from an upstream step, and the fingerprint changes at precisely that call. Change nothing, and the fingerprints match and the recording is served. Divergence is *detected, never declared*. You don't report what you changed; replay finds out, at the exact step where your change first matters. There is nothing for you to keep in sync, so there is nothing for you to get wrong.

One honest limit before you lean your weight on this: replay serves recorded answers, but once a run goes live past the divergence point, the live part touches the real world again. A pipeline with side effects needs an environment you can reset, same as any other integration test.

## The ceiling

So: experiments are cheap now. You try five drafter instructions in an afternoon, replaying the first two steps free every time. Version C *feels* warmer. Version E *seems* more concrete.

Feels. Seems. You've lowered the price of trying things and left the judging exactly where it was: your gut, reading a handful of replies, at 6pm, hungry. You have twenty recorded runs and no number attached to any of them. If version C is better, better *at what, by how much, says who?*

Cheap experiments demand a definition of success, or they're just cheap. What does "better" even mean?
