One enum classified one email. Cute. But watch what your support desk actually does with a ticket, and count the questions being answered in a single read:

What kind of problem is this? How upset is this person? Did they mention an order? What would I tell a coworker this ticket says, in one sentence? And, quietly, underneath all of it: *how sure am I about any of this?*

Five questions. Your Chapter 1 contract answers one. The temptation, trained into you by years of prompt engineering, is to fix that with more prose: "Also extract the order ID if present, and rate the customer's mood, and please also include..."

Stop. Every one of those asks is a *type decision*, and you have a type system sitting right there.

## Five questions, five types

Take them one at a time, and notice that each question already knows what shape its answer should be.

**How upset is this person?** That's not an essay question. It's multiple choice, and multiple choice is an enum:

```rust
use dspy_rs::Schema;

#[Schema]
#[derive(Clone, Debug)]
enum Mood {
    Calm,
    Confused,
    Frustrated,
    Furious,
}
```

**Did they mention an order?** Maybe. That "maybe" is the whole point. Half of prompt engineering's worst hacks exist because models pad silence with guesses; ask for an order ID that isn't there and a helpful model will invent one. The fix isn't a sterner instruction. It's a type that makes absence a legal answer:

```rust
#[Schema]
#[derive(Clone, Debug)]
struct OrderRef {
    /// The order number exactly as the customer wrote it
    order_id: String,
    /// The sentence of the ticket where it appears
    quote: String,
}
```

An `Option<OrderRef>` gives the model formal permission to say "nothing to report." Permission to be honest is the most underrated feature a contract can have. And note what `OrderRef` is: a nested struct, with its own field docs, that the model will fill like a form. `#[Schema]` is what makes any custom type legible to the machinery; enums, structs, and combinations thereof all work.

**How sure are you?** A bare `f64` called `confidence` is a number wearing a trench coat. Nothing stops the model from returning `1.5`, and nothing tells it that `0.92` should mean something. So the contract grows rules:

```rust
#[check("this >= 0.0 and this <= 1.0", label = "confidence_range")]
```

A `#[check]` is a soft constraint: the call still succeeds, and the pass/fail verdict is recorded where you can read it. Its stricter sibling `#[assert]` is a hard constraint: violate it and the call fails with a typed error. The rule of thumb writes itself. Assert what would corrupt your system. Check what you merely want to watch.

## The full contract

Put all five answers into one signature:

```rust
use dspy_rs::Signature;

/// Extract the facts a support agent needs from a Sourdough ticket.
/// Do not guess. If a fact is not in the ticket, leave it out.
#[derive(Signature, Clone, Debug)]
struct ExtractFacts {
    /// The full text of the customer's ticket
    #[input]
    ticket: String,

    #[output]
    category: Category,

    #[output]
    mood: Mood,

    /// Present only when the customer actually references an order
    #[output]
    order: Option<OrderRef>,

    /// One sentence a busy human reads instead of the ticket
    #[output]
    #[assert("this|length > 0")]
    summary: String,

    /// How confident you are in the category, 0 to 1
    #[output]
    #[check("this >= 0.0 and this <= 1.0", label = "confidence_range")]
    confidence: f64,
}
```

Look at the docstrings while you're here, because there's a discipline to them. The struct docstring is the instruction, so it carries the one behavioral demand types can't express: don't guess. Field docstrings exist only where the name falls short: `summary` says *who it's for*, which changes what a good one looks like. There is no docstring on `category`, because `/// The category` would inform nobody. If a docstring repeats the field name, delete it. The types are already talking.

Swap the signature into your Chapter 1 `main` and run the Herman ticket through it:

```rust
let extract = Predict::<ExtractFacts>::new();

let out = extract.call(ExtractFactsInput { ticket: herman_ticket }).await?;

println!("{:?} | {:?} | conf {:.2}", out.category, out.mood, out.confidence);
println!("summary: {}", out.summary);
println!("order:   {:?}", out.order);
```

```text
Bug | Frustrated | conf 0.91
summary: Customer fears the latest update wiped their four-year-old starter's tracking data.
order:   None
```

`None`, not a hallucinated order number. The option did its job.

And that soft constraint you attached? Its verdict rides along with the result:

```rust
if let Some(meta) = out.metadata().field_meta.get("confidence") {
    for check in &meta.checks {
        println!("check {}: passed = {}", check.label, check.passed);
    }
}
```

## Say it again, slower

You have now asked a language model for an enum, a second enum, an optional nested struct, an asserted string, and a range-checked float. In one call.

And you still have not written a prompt.

Every type you chose became instructions you didn't write. The enum told the model its four legal answers. The `Option` told it that silence is acceptable. The nested struct handed it a form. The docstrings added exactly the nuance names couldn't carry, and nothing more. Richer types don't just make parsing safer; they make the *ask* sharper, because the contract is compiled into what the model reads. The contract is the prompt.

## The ceiling

Now try to improve this thing, because on Thursday you'll want to.

You have a ticket the model keeps miscategorizing, and you'd love to show it two solved examples: *this one was Billing, that one was a Bug*. Where do examples live? Not in the signature; it declares what's true of every call, and examples are baggage from particular calls. You'd also like the model to reason before it commits a category. And honestly, extraction is easy work; you'd like to run it on a cheap model and save the good one for writing replies.

Demos, strategy, model choice. None of it belongs in the contract, all of it has to live *somewhere*, and that somewhere has been hiding in plain sight since Chapter 1, inside a type you've been calling without reading:

`Predict::<ExtractFacts>::new()`.
