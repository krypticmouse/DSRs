A trace is a recording of one run: every model call, every tool call, every answer that came back. You can replay a recording later without calling the model at all, which makes tests free, fast, and repeatable.

This tutorial uses the `qa` module from [Your First Module](/docs/tutorials/your-first-module). Here it is again, compact:

```rust
use dspy_rs::{module, predict};

/// Answer the question.
#[predict]
fn draft(question: String) -> String;

/// Rate the text from 1-10.
#[predict]
fn rate(text: String) -> String;

#[dspy_rs::Schema]
#[derive(Debug)]
pub struct QaOut {
    pub answer: String,
    pub upper: String,
}

#[module]
async fn qa(question: String) -> Result<QaOut, dspy_rs::ir::RunError> {
    let drafter = draft(question.clone()).await?;
    let upper: String = {
        let d: String = drafter.draft;
        d.to_uppercase()
    };
    let checker = rate(upper.clone()).await?;
    Ok(QaOut {
        answer: checker.rate,
        upper,
    })
}
```

<Steps>
<Step title="Record a run">

Wrap the call in `capture`. It runs your module normally, and hands back both the result and the trace.

```rust
use dspy_rs::trace::capture;

let (out, trace) = capture(|| qa("replay me".to_string())).await;
let out = out?;
println!("answer: {}", out.answer);
```

The module ran live: real model calls happened. The `trace` now holds a record of each one, plus the plain Rust step in the middle. Every step you wrote is one entry in the recording.

</Step>

<Step title="Save the trace to a file">

A trace serializes to JSONL, which is plain text with one JSON object per line. Save it like any string:

```rust
let jsonl = trace.to_jsonl()?;
std::fs::write("qa_run.jsonl", jsonl)?;
```

Commit this file next to your tests if you like. It is readable, diffable text.

</Step>

<Step title="Load it back and replay">

Load the file, then run the module again inside `replay`. Use the same input as the recorded run, because replay matches each step against the recording.

```rust
use dspy_rs::{replay, ReplayMode, Trace};

let jsonl = std::fs::read_to_string("qa_run.jsonl")?;
let trace = Trace::from_jsonl(&jsonl)?;

let (replayed, report) = replay(&trace, ReplayMode::Strict, || {
    qa("replay me".to_string())
})
.await;
let replayed = replayed?;

assert_eq!(report.live, 0);
println!("served {} steps, {} live calls", report.served, report.live);
```

Here is what happened. Each time the module was about to call the model, replay stepped in and served the recorded answer instead. `report.served` counts the steps answered from the recording. `report.live` counts real model calls, and it is zero.

`ReplayMode::Strict` means: if anything about the run no longer matches the recording, refuse and report it, instead of quietly calling the model. That is exactly what you want in a test. A passing strict replay proves your pipeline still behaves as it did when you recorded it, and it costs nothing to run.

</Step>
</Steps>

## Why this is useful

- Tests that cover real model behavior, with no API key and no cost in CI.
- The same run, every time. No flaky answers.
- If you change your pipeline in a way that breaks the recording, strict replay fails loudly and tells you where.
